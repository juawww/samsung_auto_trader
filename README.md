# Samsung Auto Trader

## 1. 프로젝트 개요

본 프로젝트는 한국투자증권 Open API의 모의투자 환경을 이용하여 삼성전자(`005930`)를 대상으로 자동매매 흐름을 구현한 Python 프로그램이다.

REST API만 사용하였으며, WebSocket은 사용하지 않았다. 또한 API 호출을 과도하게 반복하지 않도록 일정한 polling interval을 두고 자동매매 루프를 실행하도록 구성하였다.

본 프로그램은 실거래가 아닌 모의투자 환경에서 동작하는 학습용 자동매매 프로그램이다.

---

## 2. 거래 대상

본 프로젝트의 거래 대상은 삼성전자이다.

- 종목명: 삼성전자
- 종목코드: `005930`
- 시장: 국내 주식시장
- 거래 방식: 한국투자증권 Open API 모의투자 REST API

---

## 3. 주요 기능

본 프로그램은 다음 기능을 수행한다.

1. 환경변수 기반 API 인증 정보 관리
2. access token 발급 및 당일 token 재사용
3. 삼성전자 현재가 조회
4. 계좌 잔고 및 보유종목 조회
5. 삼성전자 보유 수량 확인
6. 평균매입가 확인
7. 최근 종가 조회
8. 5일/20일 이동평균 계산
9. 이동평균선 기반 매수/매도 신호 판단
10. 평균매입가 대비 익절/손절 조건 판단
11. 조건 충족 시 지정가 매수/매도 주문 요청
12. 주문 후 잔고 재조회
13. 주문 전후 계좌 상태 비교
14. 거래 가능 시간에만 자동매매 루프 실행
15. 주요 실행 과정 로그 출력

## 5. 실행 환경

본 프로젝트는 Python 기반으로 작성되었다.

필요 패키지는 다음과 같다.

```text
requests
python-dotenv
tzdata
```

패키지 설치 명령어는 다음과 같다.

```bash
python -m pip install -r requirements.txt
```

Windows 환경에서 `Asia/Seoul` 시간대 오류가 발생할 수 있으므로 `tzdata`도 `requirements.txt`에 포함하였다.

## 6. 환경변수 설정

프로젝트 실행을 위해 프로젝트 루트 폴더에 `.env` 파일을 생성해야 한다.

`.env.example` 파일을 참고하여 다음 값을 입력한다.

```env
GH_ACCOUNT=12345678-01
GH_APPKEY=your_app_key
GH_APPSECRET=your_app_secret
KIS_BASE_URL=https://openapivts.koreainvestment.com:29443
```

각 환경변수의 의미는 다음과 같다.

| 변수명 | 의미 |
|---|---|
| `GH_ACCOUNT` | 한국투자증권 모의투자 계좌번호 |
| `GH_APPKEY` | Open API app key |
| `GH_APPSECRET` | Open API app secret |
| `KIS_BASE_URL` | 한국투자증권 모의투자 API base URL |

보안을 위해 실제 `.env` 파일은 GitHub에 업로드하지 않는다. `.gitignore`에 `.env`를 포함하여 API key, app secret, 계좌번호가 노출되지 않도록 처리하였다.

## 7. 실행 방법

터미널에서 프로젝트 폴더로 이동한 뒤 다음 명령어를 실행한다.

```bash
python main.py
```

정상 실행 시 다음과 같은 로그가 출력된다.

```text
기존 access token을 재사용합니다.
삼성전자 모의 자동매매 프로그램 시작
거래 대상: 삼성전자(005930)
거래 시간: 09:10:00 ~ 15:30:00
반복 간격: 300초
주의: 본 프로그램은 모의투자 환경 전용입니다.
```

장 시작 전이라면 다음과 같이 대기한다.

```text
아직 자동매매 시작 전입니다. 09:10까지 대기합니다.
```

## 8. 거래 시간 기준

본 프로젝트는 삼성전자 국내주식을 대상으로 하므로 한국 주식시장 시간을 기준으로 자동매매를 수행한다.

```text
자동매매 시작 시간: 09:10
자동매매 종료 시간: 15:30
```

장 시작 직후의 급격한 변동을 피하기 위해 09:00이 아니라 09:10부터 자동매매가 시작되도록 설정하였다.

미국장 자동매매로 확장할 경우에는 거래 대상, API endpoint, transaction ID, 시장 시간 기준을 미국장에 맞게 변경해야 한다. 본 프로젝트는 삼성전자 국내주식 자동매매이므로 한국장 기준을 사용한다.

## 9. 기본 주문 방식

교수님 프롬프트의 기본 요구사항에 따라 현재가를 기준으로 지정가 주문을 사용한다.

기본 주문 가격은 다음과 같다.

```text
매수 주문 가격 = 현재가 - 1,000원
매도 주문 가격 = 현재가 + 1,000원
```

예를 들어 삼성전자 현재가가 322,500원이라면 다음과 같이 주문 가격을 계산한다.

```text
매수 주문 가격 = 321,500원
매도 주문 가격 = 323,500원
```

이 방식은 현재가보다 낮은 가격에 매수하고, 현재가보다 높은 가격에 매도하려는 단순 지정가 매매 구조이다.

## 10. 수익률 개선을 위한 전략 로직

기본 프롬프트에서는 현재가 기준 매수·매도 주문을 요구하지만, 실제 자동매매에서 조건 없이 반복 주문을 넣는 것은 위험할 수 있다.

따라서 본 프로젝트에서는 수익률 개선 가능성과 리스크 관리를 고려하여 다음 조건을 추가하였다.

### 10.1 이동평균선 전략

최근 종가를 기준으로 5일 이동평균과 20일 이동평균을 계산한다.

```text
5일 이동평균 > 20일 이동평균
→ 단기 상승 추세로 판단

5일 이동평균 < 20일 이동평균
→ 단기 약세 또는 하락 추세로 판단
```

### 10.2 보유 수량 조건

중복 매수를 방지하기 위해 현재 삼성전자 보유 수량을 확인한다.

```text
보유 수량이 0주
→ 매수 가능

보유 수량이 1주 이상
→ 추가 매수하지 않음
```

### 10.3 익절 조건

보유 중인 삼성전자의 현재 수익률이 평균매입가 대비 3% 이상이면 익절 매도를 고려한다.

```text
현재 수익률 >= +3%
→ 익절 매도 조건 충족
```

### 10.4 손절 조건

보유 중인 삼성전자의 현재 수익률이 평균매입가 대비 -2% 이하이면 손절 매도를 고려한다.

```text
현재 수익률 <= -2%
→ 손절 매도 조건 충족
```

## 11. 최종 자동매매 로직

본 프로그램의 최종 자동매매 흐름은 다음과 같다.

```text
1. 현재가 조회
2. 잔고 조회
3. 보유 수량 확인
4. 평균매입가 확인
5. 최근 종가 조회
6. 5일/20일 이동평균 계산
7. 매수/매도/관망 신호 판단
8. 조건 충족 시 주문 요청
9. 주문 후 잔고 재조회
10. 300초 대기 후 반복
```

구체적인 주문 조건은 다음과 같다.

```text
보유 수량이 0이고 5일 이동평균 > 20일 이동평균
→ 현재가 - 1,000원에 매수 주문

보유 수량이 있고 현재가가 평균매입가보다 3% 이상 상승
→ 익절 매도

보유 수량이 있고 현재가가 평균매입가보다 2% 이상 하락
→ 손절 매도

보유 수량이 있고 5일 이동평균 < 20일 이동평균
→ 추세 약화로 판단하여 매도 고려

그 외
→ 관망
```

이 전략은 단순 반복 주문보다 시장 추세, 보유 상태, 손익률을 함께 고려한다는 장점이 있다. 다만 수익을 보장하는 전략은 아니며, 실제 수익성은 백테스트를 통해 별도로 검증해야 한다.

## 12. 주문 후 잔고 확인

주문 요청 후에는 계좌 잔고와 보유 종목을 다시 조회한다.

이를 통해 주문 전후 계좌 상태가 달라졌는지 확인한다.

```text
주문 전 잔고 조회
→ 주문 요청
→ 주문 후 잔고 재조회
→ 주문 전후 보유종목 및 평가금액 비교
```

단, 지정가 주문은 주문 요청이 성공하더라도 가격 조건이 맞아야 실제 체결된다. 따라서 주문 요청 성공과 실제 체결 완료는 구분해서 해석해야 한다.

## 13. 토큰 재사용

`auth.py`에서는 access token을 발급받은 뒤 `token_cache.json`에 저장한다.

같은 날짜에 다시 프로그램을 실행하면 새 토큰을 발급받지 않고 기존 토큰을 재사용한다.

이를 통해 불필요한 인증 요청을 줄이고, API 호출을 더 안정적으로 관리할 수 있다.

```text
오늘 발급받은 token이 있음
→ token_cache.json에서 재사용

오늘 발급받은 token이 없음
→ 새 access token 발급
```

`token_cache.json`에는 인증 정보가 포함될 수 있으므로 GitHub에 업로드하지 않는다.

## 14. 테스트 결과

프로그램을 실행한 결과 다음 흐름이 정상적으로 작동하는 것을 확인하였다.

```text
access token 재사용
삼성전자 현재가 조회
잔고 및 보유종목 조회
이동평균선 계산
보유 수량 및 평균매입가 확인
매수/매도/관망 조건 판단
주문 후 잔고 재조회
자동매매 루프 대기
```

테스트 시점이 주말 또는 장외 시간이면 KIS Open API에서 다음과 같은 응답을 반환할 수 있다.

```text
모의투자 주문이 불가한 계좌입니다.
```

이 경우 프로그램 오류가 아니라, 모의투자 서버가 주문 가능 시간이 아니라고 판단하여 주문 요청을 거절한 것이다.

따라서 본 프로젝트에서는 조회 API와 자동매매 흐름은 정상적으로 작동함을 확인하였고, 실제 주문 접수 여부는 평일 정규 거래 시간에 추가 확인이 필요하다.

## 15. 한계점

본 프로젝트는 학습용 모의투자 자동매매 프로그램이므로 다음과 같은 한계가 있다.

1. 수익률을 보장하지 않는다.
2. 전략의 성과를 백테스트하지 않았다.
3. 지정가 주문은 체결되지 않을 수 있다.
4. 주말 또는 장외 시간에는 주문이 거절될 수 있다.
5. 현재는 삼성전자 한 종목만 대상으로 한다.
6. 거래 수수료, 세금, 슬리피지 등을 정교하게 반영하지 않았다.
7. API 응답 형식 변경 시 코드 수정이 필요할 수 있다.
8. 실거래 환경이 아닌 모의투자 환경을 기준으로 구현되었다.

## 17. 보안 관리

## 18. 주의사항

본 프로젝트는 한국투자증권 모의투자 환경을 이용한 학습용 프로그램이다. 실제 투자 판단에 사용하기 위한 프로그램이 아니며, 투자 손실에 대한 책임은 사용자 본인에게 있다.

또한 본 프로그램의 이동평균선, 익절, 손절 조건은 자동매매 로직을 실험하기 위한 단순 전략이다. 수익률을 보장하지 않으며, 실제 투자 전략으로 사용하기 위해서는 충분한 백테스트와 리스크 관리 검증이 필요하다.
